## When the seed lands — procedure

1. Unzip `public_html` into a scratch folder, **not** the repo. Remove `.htaccess`, `cgi-bin/`, `wp-*`, anything with credentials, `*.zip`/backups.
2. Copy into the repo **without overwriting** existing files (the drop is newer): `cp -rn seed/* .` — then diff `Default.html`: keep the repo's, restore the floating `/tab-menu.html` button the drop removed.
3. SiteGround served `Default.html` as the directory index. Workers serves only `index.html`. For every seeded folder whose only index is `Default.html`, add a rewrite to `_redirects`: `/folder/  /folder/Default  200` (the root already has `/  /Default  200`).
4. Read the old `.htaccess` before deleting it: each `RewriteRule`/`Redirect` becomes one `_redirects` line (the `/b/<name>` short links and extensionless routes above probably live there — or are folders with an index).
5. Re-run the link checker → **0 missing**. Run the gate on the seeded pages (report, don't rebuild).
6. Commit `seed: site as of 2026-09-23` in its own commit, before any other change.
7. **Seed everything.** The homepage redesign will later drop five worlds (Joann Fabrics, Warehouse, Oil & Gas, the five Wazoodle product experiences, The Book) — that changes nothing here: bring every file in, keep every URL alive, don't prune. The seed report lists which files belong to those worlds, for information only.
8. **Stay-or-go is unruled.** Whether those worlds' pages stay live on this domain or leave for akaswisdom.com has not been decided. If anything in the seed forces that question, stop and ask — don't decide it in the seed.
9. `/forms/` (developer exemplars) is kept out of the public build by `.assetsignore`; don't link to it from any seeded page.
